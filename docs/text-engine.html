ENGINE ROOM / 02

The text engine.

A first-pass source study of buffers, snapshots, rope storage, stable positions, operation queues, and undo history.

1. Buffer and snapshot model

The text subsystem's Buffer and BufferSnapshot live in crates/text/src/text.rs.

The inspected Buffer structure carries state for a snapshot, history, deferred operations, replica tracking, a Lamport clock, subscriptions, and version waiters. The inspected BufferSnapshot includes visible_text, deleted_text, fragment and insertion indexes, an undo map, version information, replica/buffer identifiers, and line-ending metadata.

VERIFIED - the snapshot is not just a wrapper around one mutable string. The inspected structure keeps visible and deleted text separately and carries fragment/operation-related indexes.

ANALYSIS - this shape is consistent with a model that preserves edit identity and deletion state alongside the currently visible text. It provides data structures that can participate in history and synchronization.

2. Rope and SumTree

crates/rope/src/rope.rs defines Rope over a SumTree<Chunk>. Chunk implementation is in crates/rope/src/chunk.rs.

The inspected chunk structure stores text alongside bitmap indexes for character boundaries, UTF-16 units, newlines, and tabs.

VERIFIED - the rope uses a summary-indexed tree of chunks, and each chunk maintains coordinate-related metadata.

ANALYSIS - this arrangement is designed to accelerate conversions between byte offsets, character/UTF-16 positions, and row/column coordinates. Actual complexity and performance depend on the exact seek and update paths.

3. Locator and stable ordering

The locator implementation is in crates/text/src/locator.rs. The inspected Locator is backed by a small vector of integer components. Its between(lhs, rhs) operation constructs an ordered identifier between existing positions.

Tests exercise large sequential append patterns and repeated insertion at a cursor. These scenarios are useful evidence about intended workloads, not a universal complexity guarantee.

ANALYSIS - stable position identifiers can avoid renumbering all subsequent items after an insertion. The existing tests suggest common typing patterns are an optimization target.

4. Operation queue

The queue implementation is in crates/text/src/operation_queue.rs. The inspected insertion path sorts operations by Lamport timestamp, deduplicates matching timestamps, and inserts the result into its tree-backed structure.

The semantic guarantees around duplicate identity, causal readiness, and interaction with replicas require following the operation application code.

5. History and undo

The History struct and its implementation live in crates/text/src/text.rs; undo state is represented in crates/text/src/undo_map.rs.

The inspected history structure includes a base rope, an operation map, undo/redo stacks, transaction depth, and a grouping interval. The undo map tracks edit/undo identifiers and an undo count.

ANALYSIS - undo is integrated with operation identity rather than being only a stack of string reversals. Its behavior in the presence of concurrent replicas still needs explicit tracing.

6. End-to-end edit lifecycle

The full trace is documented in One edit. Many layers.. It follows the language-facing edit API through operation creation, fragment mutation, anchor identity, undo/redo, and causal remote replay.

7. Collaboration, invariants, and adversarial testing

The next layer of the investigation is now documented in two connected studies: the collaboration lab walks through independent replicas and operation delivery; Invariants under pressure audits check_invariants, the randomized network harness, known regressions, and the remaining conflict test matrix.

OPEN HYPOTHESIS - the tests provide evidence for the scenarios they exercise. A formal, universal convergence guarantee has not been established by this source review.

Evidence vocabulary

  • Verified: directly supported by the inspected implementation or tests.
  • Analysis: interpretation of the observed implementation.
  • Hypothesis: unresolved claim that needs more inspection or measurement.
